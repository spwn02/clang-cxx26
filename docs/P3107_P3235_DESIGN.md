# P3107R5 and P3235R3 print implementation

## Scope

P3107R5 permits `std::print` to avoid formatting the complete result into a
`std::string` when every argument opts into
`enable_nonlocking_formatter_optimization`. P3235R3 extends that opt-in to
additional standard-library formatters. Neither paper specifies a particular
buffer class, nor does P3235R3 require a second parser for bare `{}` fields.
The live C++ working draft retains `vformat` for the deliberately buffered
`vprint_*_buffered` functions and specifies the non-buffered functions in
terms of output while holding the stream lock.

## Design

The non-buffered FILE* and `ostream` implementations will call `vformat_to`
with a libc++ internal output iterator. The iterator owns a fixed-size byte
or wide-character buffer and flushes bounded chunks to its target. It never
owns the complete formatted result. A final explicit flush is required;
destruction does not perform I/O, so write errors are reported before the
print function returns.

The FILE* adapter uses `fwrite` and preserves the existing `feof`/`ferror`
mapping to `system_error(EIO)` or the stream's error number. The `ostream`
adapter uses `sputn`; a short write sets `badbit | failbit` through the
existing exception-aware path. Formatting exceptions remain outside that
write-error conversion path, preserving the sentry and exception-mask rules.

The Windows native Unicode-terminal path remains string-based in the first
implementation step. It must transcode UTF-8 to UTF-16 before calling
`WriteConsoleW`, and its existing intermediate buffer has different element
type and ownership requirements. The non-terminal path still uses the direct
FILE* writer.

The existing `vprint_*_buffered` semantics are unchanged. Tests will inspect
write call sizes for output larger than the internal buffer and inject a
mid-output write failure, in addition to checking byte-for-byte output.
